# Base44 Development Environment

## Project Overview

FitFlow — a TanStack Start (SSR) app generated by Lovable. Vite dev server with Nitro SSR. Uses Bun as package manager. Connects to a remote Supabase instance for auth and data; Paddle for payments.

## Setup

```sh
docker compose -f docker-compose.base44.yml up -d --build
```

The app runs on **port 3000** (Vite dev server with SSR). Health check: `GET /`.

## Key Details

- **Package manager**: Bun (`bun.lock`, `bunfig.toml`). Install with `bun install --frozen-lockfile`.
- **Dev command**: `bun run dev` → `vite dev -- --port 3000 --host 0.0.0.0`
- **Framework**: TanStack Start (file-based routing in `src/routes/`), TanStack Router, TanStack Query, React 19, Tailwind CSS v4.
- **SSR**: TanStack Start uses Nitro. Server entry at `src/server.ts`. Dev server handles both client and SSR.
- **Vite config**: `@lovable.dev/vite-tanstack-config` bundles plugins (tanstackStart, viteReact, tailwindcss, tsConfigPaths, nitro, sandbox detection). Do NOT add these plugins manually.

## Environment Variables

- `.env` — Supabase URL + publishable key (public, client-safe). Already in repo.
- `.env.development` — `VITE_PAYMENTS_CLIENT_TOKEN` (Paddle test token). Already in repo.
- `/run/base44/app.env` — platform-managed secrets (if any are added later).

### Optional secrets (not required for boot)

These are only needed for specific features (admin, payments). The app boots and renders without them:

- `SUPABASE_SERVICE_ROLE_KEY` — server-side admin Supabase access (bypasses RLS). Used by `src/integrations/supabase/client.server.ts`.
- `PADDLE_SANDBOX_API_KEY` — Paddle sandbox payments. Used by `src/lib/paddle.server.ts`.
- `LOVABLE_API_KEY` — Paddle gateway auth. Used by `src/lib/paddle.server.ts`.
- `PAYMENTS_SANDBOX_WEBHOOK_SECRET` — Paddle webhook verification.

## Architecture Notes

- Public routes: `/` (landing/pricing), `/pricing`, `/integritetspolicy`, `/sitemap.xml`.
- Authenticated routes: `/hem`, `/profil`, `/ovningar`, `/schema/*`, `/nutrition/*`, etc. — require Supabase auth.
- Supabase client (`src/integrations/supabase/client.ts`) uses publishable key (lazy-init via Proxy).
- Server-side admin client (`src/integrations/supabase/client.server.ts`) uses service role key (lazy-init, only fails when accessed).
- Lovable cloud auth (`src/integrations/lovable/index.ts`) wraps OAuth flows.
